=== ANCHOR: ### S05.4 — `awk` filters, totals, and shell variables ===
**TRAINER ONLY — make R2 concrete with an injection (observed 2026-10-19).** Splicing a shell variable into the awk *program* is code construction: `d='/ {print "PWNED"} END{print 0} #'; awk '$9 ~ /^'"$d"'/ {c++} END{print c+0}' ex.log` prints `PWNED` for every line — the value became awk code. The same value passed with `-v d="$d"` is treated as a pattern string and the filter simply reports `0`. Teaching line: "`-v` passes *data*; quoting the value into the program passes *code*." This is the third appearance of the course's one security rule (M01 `source`d config, M04 `source` vs parse, here awk) and it returns in M09 (`stackctl` parses `envs/*.conf`). *Also observed:* without `-v`, `("^" d)` with `d` unset matches every line (`6`), and the literal `/^$d/` matches none (`0`) — two silent failures, neither an error; that is why R2 asks for a mechanism.

=== ANCHOR: ### S05.5 — `sed`, here-documents, here-strings, process substitution ===
**TRAINER ONLY.** *Ask:* "Why does `diff` need `<( )` when `grep` did not?" *Expected:* "`grep` reads stdin; `diff` wants two *files* — process substitution gives a pipeline a file name." *Observed error to show:* `sed 's/.*" ([0-9]{3}) .*/\1/'` without `-E` → `invalid reference \1 on …s' command's RHS` (backtick in the message elided) — the group was never opened because `(` is literal in basic regex. *Misconception:* here-doc vs here-string — `<<'EOF'` is many lines into stdin (quote the delimiter to stop expansion, as the course always does); `<<<` is one string. `logsleuth`'s `usage()` is a here-doc; M06 reuses it.

=== ANCHOR: ## LAB-05 — Your exercise (graded as A-06) — 55 min ===
**TRAINER ONLY — complete solution (reference `solution/reports.sh`, observed 5/5):**
```bash
#!/usr/bin/env bash
# Lab 5 solution — the counting pipeline and an awk filter.

# top_ips: the N most frequent client IPs (field 1), "<ip> <count>" most first.
top_ips() {
  local f="$1" n="$2"
  awk '{print $1}' "$f" | sort | uniq -c | sort -rn | head -n "$n" | awk '{print $2, $1}'
}

# count_class: how many lines have a status (field 9) starting with <digit>.
count_class() {
  local f="$1" d="$2"
  awk -v d="$d" '$9 ~ ("^" d) {c++} END{print c+0}' "$f"
}
```
*Acceptable variations:* `cut -d' ' -f1` instead of the first `awk` (passes on the fixture); `sort | uniq -c | sort -k1,1nr` (passes); `awk '$9 ~ /^'"$d"'/'` (passes the grader, **fails R2** — this is the injection pattern; coach it out). A `count_class` without `+0` passes the grader (no class is empty in the fixture) but fails on an empty class — mention it in feedback. **A tempting wrong turn, observed:** `grep -c " $d[0-9][0-9] "` gives `70` for 4xx and `55` for 5xx — it also matches byte counts such as ` 420 ` and ` 512 `; the grader catches it (`expected [50], got [70]`), and it is a good moment to say why the course keys on *field 9* rather than on a pattern anywhere in the line.
