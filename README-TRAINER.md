# Bash Scripting — zero to hero, project-based · Full Trainer Edition

This package contains everything in the Student Edition **plus** the material that must never
reach a student-visible area. Read `README-STUDENT.md` for the learner's view of the same tree.

## Trainer-only material — keep out of student Moodle areas

| Path | What it is |
| --- | --- |
| `trainer/*.md` | Every lesson page again, with 🧑‍🏫 **TRAINER ONLY** boxes: preparation with observed grader counts, a facilitation plan, per-step teaching notes, the complete solution, grading descriptors (Not met / Met / Strong), worked scoring, calibration samples, model feedback, remediation and an equivalent reassessment. |
| `trainer/callouts/` | The source of those boxes, one file per module. Edit these, then rebuild the page: `python3 tools/merge_trainer.py student/M05-text-pipelines.md trainer/callouts/M05.callouts.md > trainer/M05-text-pipelines.md`. |
| `trainer/a10r/` | The A-10R reassessment kit (`linetool`): task, grader, starter, reference solution. |
| `trainer/CAP01-capstone-stackctl.md` | Includes the CAP-01R fault list F1–F9 with injection commands and solutions. |
| `labs/*/exercise/solution/` | The reference solution of every lab (the grader passes 100 % on it). |
| `labs/capstone/lab.sh` | The A-10-scope walkthrough. |
| `prove_all.sh` | Runs every demonstration, every grader on its starter and its solution, the `logsleuth` suite and the shellcheck gate. Must end with `ALL GREEN`. |
| `BLUEPRINT.md` | The course design: parameters, skills model, traceability, course map, assessment plan, capstone contract, quality gates, open verification tasks. |
| `CONTINUATION-MANIFEST.md` | The logbook: every change, decision and correction, and the Notion page IDs. Read it first when maintaining the course. |

## Before the first cohort

1. `bash prove_all.sh` on your machine — expect `ALL GREEN`.
2. Do the verification tasks still open at release and record the dates in `BLUEPRINT.md` §13:
   **V-01** build `env/Dockerfile` and run `tools-check.sh` + `prove_all.sh` inside it;
   **V-02** check the current Docker install/licensing pages;
   **V-03** attach GNU Bash manual / ShellCheck wiki citations;
   **V-04** run `labs/lab9-stackctl/exercise/solution/tests/live-smoke.sh` for `test` and `prod` and `tools/record-manifest.sh` on a machine with a Docker daemon and network (the first `up` builds the fraud-clf image) — the M09 and CAP-01 pages depend on it;
   **V-05** pilot with learners.
3. Decide who reviews A-10/CAP-01 and observes CAP-01R (`BLUEPRINT.md` §6). Without a reviewer, completion is self-assessed.

## Building the archives

```bash
bash tools/package-all.sh        # → dist/bash-course-{student,trainer}{,-ubuntu,-macos,-windows}.zip
```

Eight archives: Student and Trainer, each as the all-platform master and three platform editions
(Ubuntu/Debian, macOS, Windows 11 via WSL 2 Ubuntu). The platform editions are generated by
`tools/build_os.py` from `<!-- os:… -->` markers in the pages and `tools/os-variants.json`; they differ
from the master only in Environment, M00, M01, M03, M09 and CAP-01. `EDITION.txt`, when present, names
the edition this archive is. Edit only the master and rebuild.

Every student archive is checked by `tools/leakcheck.sh`, which fails on any solution, trainer page,
callout, the A-10R kit, the capstone walkthrough, `TRAINER ONLY` text, stray `work/`/`.render/`/lock
files, or a 64-hex digest.
